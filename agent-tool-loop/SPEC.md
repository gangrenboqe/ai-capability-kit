---

## 一、目标（一句话）

让模型能自主选择并调用本地工具，把"只能聊天"变成"能动手干活"。

---

## 二、交付物（缺一不算完成）

1. `agent_loop.py` —— 调用循环：发消息 → 模型返回 tool_calls → 执行 → 回填结果 → 模型继续 → 直到不再要工具
2. `tools/` —— **至少 3 个真实可用工具**，每个一个文件
3. `tests/` —— 单元测试，**必须覆盖正常 / 异常 / 空数据三类分支**
4. `README.md` —— 含：装什么、怎么跑、每个工具干什么、**一条命令跑测试**
5. `out/` + `SAMPLE_REPORT.md` —— **一次真实运行的完整调用链记录**（脱敏）

---

## 三、至少 3 个工具（建议这三个，也可换但要说明理由）

| 工具 | 作用 | 演示什么能力 |
|---|---|---|
| `search_history` | 按关键词查本地 SQLite 里的历史会话 | 与项目②检索联动 |
| `count_chars` / `calc` | 算数或文本统计 | 参数校验（数字/表达式非法要报错） |
| `read_note` | 读取指定文本文件 | 路径越界要拦住 |

---

## 四、技术约束（🔴 硬要求）

| # | 约束 | 理由 |
|---|---|---|
| 1 | **零第三方依赖**，只用 Python 标准库 | 与主项目一致，这是他的核心卖点 |
| 2 | **禁止硬编码路径分隔符**，一律 `pathlib.Path` | 跨平台 |
| 3 | **读写文件一律显式 `encoding='utf-8'`** | 他在这上面栽过（中文命令导致 CI 全红） |
| 4 | **不写死 API Key**，只走环境变量 | 项目铁律 |
| 5 | Python **3.11 与 3.13 都要能跑** | CI 已覆盖这两个版本 |

---

## 五、验收标准（🔴 逐条可复算，交接时要给数字）

- [ ] **1. 工具调用循环真的跑通**：给一个必然需要工具的问题，模型能选对工具并用结果回答
- [ ] **2. 选对工具正确率可量化**：**≥20 条固定用例**，记录正确条数 / 总条数
- [ ] **3. 参数校验**：缺字段、类型错、越权路径 → **明确报错信息**，不崩、不静默
- [ ] **4. 异常兜底**：工具内部报错时，模型能收到错误信息并继续回答，而不是整个请求失败
- [ ] **5. 调用链可复现**：日志能回放一次完整调用（每轮：模型说了什么、要调什么、参数是什么、返回了什么）
- [ ] **6. 测试覆盖三类分支**：正常 / 异常 / 空数据，**不许只跑 happy path**
- [ ] **7. 跨平台**：CI 在 **Ubuntu + Windows** 都绿（macOS 若能加更好）
- [ ] **8. README 里的命令我能直接复制跑通**（不许出现"请先自行配置 XX"）

## 六、不做什么（边界，防止发散）

- ❌ 不改主项目现有代码（要复用就 import，不要为了"更优雅"重构它）
