# 说明 - 工具调用循环

> 项目：agent-tool-loop · 读者：完全不懂技术的第一次求职者 · 写作日期：2026-10-11

## ① 一句话是什么

让助手能「用工具干活」并循环到做完为止的一套流程。

## ② 为什么需要它

助手（大模型，LLM，Large Language Model，用海量文本训练出来的语言程序）本质上只会「生成文字」，不会真的做事。你问它「帮我算这三个月一共花了多少钱」，它可能顺口编一个数字——因为它没有真的去算。

有了这套流程，助手先发出一个「我要用计算器」的请求，程序执行后把真实结果送回给它，它再基于真实结果回答。工具调用（Function Calling，函数调用，让助手按约定格式发出「我要用某个工具」的请求）解决「会用工具」的问题；循环（Agent Loop，智能体循环，工具结果送回助手、它再决定下一步，直到给出最终答案）解决「多步任务能做完」的问题。

没有它会怎样：助手只能靠猜，遇到「先查记录、再算结果」这类多步任务，一步都做不下去。

## ③ 在我们项目里长什么样

- 核心代码在 [agent_loop.py](agent-tool-loop/agent_loop.py) 的 `run_loop` 函数
- 配套三个工具（都在 `tools/` 目录）：`calc.py`（计算器）、`read_note.py`（读笔记）、`search_history.py`（搜历史会话）
- 助手要工具时，按约定格式发出请求；程序执行后把结果以 JSON（JavaScript Object Notation，一种人和程序都能读懂的键值对文本格式）回填给助手，它再决定继续用工具还是收尾
- **工具失败不中断**：失败时返回 `{"ok": false, ...}`，错误原因原样回填给助手，让它知道「这条路不通」，可以换思路，而不是编一个答案
- **步数有上限**：超出上限就停止，防止助手反复调用同一个工具停不下来
- 实测数字：20 条「选对工具没有」的评测用例全对（20/20）；演示脚本 `demo.py` 跑 3 轮对话用时 3.7 毫秒；全部测试 70/70 通过（Python 3.11.7 与 3.13.13 双版本）

## ④ 面试怎么讲（约 45 秒）

「我做过一个带工具调用的循环框架。助手收到问题后，先决定要不要用工具；要用，就按固定格式发出工具请求，我执行完把结果以 JSON 回填给它，它再决定继续用工具还是给出最终回答。有两个关键设计：一是工具失败不中断流程，错误信息原样回填给助手，让它自己换思路，而不是硬编一个答案；二是循环步数有上限，防止极端情况下停不下来。工具选对率我用 20 条评测用例测过，全对。我的体会是：智能体循环的关键不在模型多聪明，而在『执行结果怎么可靠地送回模型』这件事上。」

## ⑤ 常见误解 / 坑

- **误解**：「助手自己会算数」。不会，它只是在生成文字，数字可能凭空编造。必须让它调用真正的计算器工具。
- **我们踩过的坑（设计层面）**：工具报错时如果直接中断流程，助手就不知道失败原因，容易编一个像模像样的答案。我们的做法是把错误也当成一种「结果」回填。
- **坑**：不给循环设步数上限，极端情况下助手会反复调用同一个工具，程序停不下来。
