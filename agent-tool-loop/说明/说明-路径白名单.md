# 说明 - 路径白名单

> 项目：agent-tool-loop · 读者：完全不懂技术的第一次求职者 · 写作日期：2026-10-11

## ① 一句话是什么

读文件前先查地址，只许读指定文件夹里的文件。

## ② 为什么需要它

助手想读你的笔记，但如果对「读哪个文件」不设限制，它也可能被引导去读密码文件、系统配置——就算是你无意间说漏的一句话，都可能让它把不该读的内容读出来、写进对话记录。

把可读范围限定在一个白名单目录（只允许访问的文件夹清单）里，即使模型被带偏，最坏结果也只是「读不到东西」，不会泄密。

没有它会怎样：读文件工具等于一把不设防的万能钥匙。

## ③ 在我们项目里长什么样

- 代码在 [tools/read_note.py](agent-tool-loop/tools/read_note.py)
- 只允许读项目 `notes/` 目录下的文件（目录里有 `roadmap.md`、`todo.txt`、`meeting_notes.txt` 三个样例笔记）
- 防路径穿越（Path Traversal，用「..」这类符号跳出指定文件夹、读到别处文件的攻击手法）：拒绝包含「..」的写法，并核对解析后的真实落点仍在白名单目录内
- 单文件上限 64KB：防止读一个超大文件把整个循环拖死
- 读不到、超限、越界，都返回 `{"ok": false, ...}` 的失败说明，不崩溃
- 测试：[tests/test_read_note.py](agent-tool-loop/tests/test_read_note.py) 覆盖正常读取、越界、不存在等分支；属全部 70 条测试的一部分

## ④ 面试怎么讲（约 40 秒）

「读文件这个工具我做了三层防线：第一，地址必须落在指定的笔记目录里；第二，拒绝包含『..』的路径，防路径穿越攻击跳出目录；第三，单文件 64KB 上限，防止超大文件把程序拖死。三层任何一层不过，就返回带原因的失败结果，而不是崩溃。这个设计让我体会到：工具一旦暴露给模型，它的每一个参数都要当成不可信输入来防，哪怕模型平时表现再正常。」

## ⑤ 常见误解 / 坑

- **误解**：「模型是自己人，它传来的路径不用防」。模型的输出可能被外部对话内容影响，必须一律当外部输入对待。
- **我们踩过的坑（设计层面）**：只在字符串里搜「..」不够稳——不同写法、不同拼接方式都可能绕过。正确做法是解析出真实落点，核对它是否仍在白名单目录内。
- **坑**：不限制文件大小。读一个几 GB 的日志文件，整个程序会卡到没法用。

## ⑥ 关联词

- 工具调用循环（读笔记是它的三个工具之一）
- 白名单计算器（同一个「只放行确认安全的」思路）
- 错误回填（失败结果 `{"ok": false}` 回填给助手继续对话）
