# AI 能力工具集（ai-capability-kit）

> 三个工具回答同一类问题：**怎么证明一个 AI 功能真的能用，而不是"跑起来看着像"。**

---

## 这是什么

| 工具 | 解决什么 | 谁用得上 |
|---|---|---|
| [agent-tool-loop/](agent-tool-loop/) | 让模型不只会说话，**会调工具、会用真实结果回答**（带步数上限与失败回填） | AI 应用 / Agent 岗 |
| [local-retrieval/](local-retrieval/) | 本地知识库检索：自己分词 + SQLite FTS5 全文索引 + BM25 排序 | AI 应用 / 数据岗 |
| [prompt-eval/](prompt-eval/) | 提示词 A/B 评测：25 条用例 + 客观断言打分，**四版提示词跑出可复现的分数** | AI 应用 / 质量 / 提示词工程 |

---

## 怎么跑

```bash
# 1. Agent 工具调用循环（带离线模拟后端，评测确定性）
cd agent-tool-loop && python demo.py && python eval_selection.py

# 2. 本地检索
cd local-retrieval && python demo.py

# 3. 提示词评测（离线确定性模拟后端）
cd prompt-eval && python run.py --compare
```

**测试**（纯标准库，毫秒级）：

```bash
cd agent-tool-loop && python -m unittest discover -s tests   # 70 项
cd local-retrieval  && python -m unittest discover -s tests   # 32 项
cd prompt-eval      && python -m unittest discover -s tests   # 42 项
```

全部在 **Python 3.11 与 3.13 双版本**下验证通过。**依赖：无。**

## 🔴 三条我刻意写进文档的诚实边界

这一节是整个工具集**最该被先读**的部分：

1. **工具调用循环的 20/20 用的是离线模拟后端**（`ScriptedBackend`）——
   真实大模型**未实测**（当时无密钥）。**模拟成绩 ≠ 真模型成绩。**
2. **提示词评测同理**：`OfflineSimModel` 测的是"提示词守则被遵守的程度"，
   **不是真实模型的能力排名**。
3. **本地检索的速度是区间不是定值**（随机器与负载波动），
   文档里给的是**多次实测的区间**，单次精确值以 `out/eval_report.md` 为准。

> 为什么把这段放在最前面：**把"模拟跑通 20/20"写成"模型能力验证通过"，是自欺欺人。**
> 我宁愿让人先看到边界，再看成绩。

## 几个设计上花了心思的地方

**· 索引缺 FTS5 就明确报错，不静默降级。**
环境里没有编译 FTS5 扩展时，程序带着明确说明停下，而不是悄悄变成慢搜索——
**宁可明确失败，不做静默降级。**

**· 内容指纹做幂等。**
每篇文档算 SHA-256 指纹，重复导入分"插入/更新/跳过"三种结果，认内容不认文件名。

**· 提示词草稿被回退这件事写进了表格。**
`v3_draft` 得分 18 比 `v2` 的 23 低，所以被回退，README 与对比报告都写明了
**演进顺序是 v1 → v2 → v3_draft → v3**。**做错了还留着证据**，比藏起来可信。
