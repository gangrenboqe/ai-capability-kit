# 说明 - 离线模拟模型

> 项目：prompt-eval · 读者：完全不懂技术的第一次求职者 · 写作日期：2026-10-11

## ① 一句话是什么

一个照着守则演戏的假助手，让考试不花钱、天天能跑。

## ② 为什么需要它

和 agent-tool-loop 项目的理由相同：真模型要花钱、要密钥、每次输出都不一样，没法当稳定的考生。四版提示词比成绩，前提是「同样的守则怎么写、考生就怎么表现」，否则分数差异说不清是守则的功劳还是模型的心情。

离线模拟模型（OfflineSimModel，Offline Simulation Model，不联网、按规则回应的假模型）就是这位标准考生。它和真模型实现同一套接口（Interface，程序之间约定的调用方式），所以真模型接进来时评测流程一行不用改。

没有它会怎样：评测要么烧钱且不可复现，要么根本跑不起来。

## ③ 在我们项目里长什么样

- 代码在 [backend.py](file:///E:/DSHPersonalAI/projects/prompt-eval/backend.py) 的 `OfflineSimModel`
- 它把系统提示词里的指令当开关：
  - 看到「只输出 JSON」→ 输出 JSON
  - 看到「不知道就说不知道」→ 遇到不会的就承认不知道
  - 看到「拒绝执行」类指令 → 拒绝
  - 看到「用计算器工具」→ 调用工具
  - 「30 字以内」「一律不超过 20 字」→ 各有对应行为
- 所以 v3_draft 那次 18/25 的回退能完整复现——正是「一律不超过 20 字」这个开关触发的
- **诚实边界（必须讲清）**：它不是真实大模型。这份成绩测的是「守则写得清不清楚、断言可不可判」，是规则照做程度的实测；真实大模型表现**未验证**（无密钥），README 和样例报告都标注了
- 测试：[tests/test_backend.py](file:///E:/DSHPersonalAI/projects/prompt-eval/tests/test_backend.py)，属全部 42 条测试的一部分

## ④ 面试怎么讲（约 50 秒）

「prompt-eval 的考生是个模拟模型。它把系统提示词当剧本：守则里写『只输出 JSON』它就输出 JSON，写『不知道就说不知道』它遇到不会的就承认不知道。为什么这么设计？因为这样四个版本的成绩差异就能完全归因到守则本身，而不是模型的状态波动。必须说明：它不是真模型，这份成绩验证的是评测流程的可信度和提示词的可执行性，真实大模型的表现未验证。我认为评测框架的价值在流程可信——真模型只是其中一个可替换的部件。」

## ⑤ 常见误解 / 坑

- **误解**：「模拟模型的成绩等于真模型成绩」。不是。它验证的是评测流程和守则的可执行性，不代表真模型表现。
- **我们踩过的坑（原则层面）**：不写清楚这一点，成绩单就成了虚假宣传。所以 README、样例报告、面试稿三处都标注「真实大模型未验证」。
- **坑**：模拟模型照剧本演，演不出真模型跑题、复读等真实毛病——这是已知局限，答辩要主动承认。
